# 微信公众号封面 V2 试验设计

## 目标

针对潜界 AI 的海外创业志、X 商业情报、产品猎人日报及 TrustMRR 榜单，解决微信图文列表中大图中央文字重复、小图文字不可读、封面与当期文章不匹配的问题。先以数日观察为试验期，不改变公众号实际群发或发表机制。

## 既有系统与约束

- 统一投递器 `mp-publisher` 在硅谷服务器运行，仅执行 `draft/add`，永不自动公开发布。
- 现有五个封面池（TrustMRR 周、月分开）每池三个永久 MediaID。通过 `source_key` 的哈希选择，所有封面是 900×383 海报，中央有大量固定文字。
- 微信同一篇 `news` 使用一个 `thumb_media_id`，再按 `pic_crop_235_1` 和 `pic_crop_1_1` 分别裁剪横版与方版。素材 ID 属于私有数据，禁止进入仓库、日志或监控。
- 无额外图片 API 费用、无法保证每日都生成独一无二的图片。首先保留静态素材池和明确的人工覆盖入口，为之后接入每期生成器预留接口。

## 方案比较

1. **继续纯哈希 + 只换图**：成本和风险最低，但文章主题与封面不相关。
2. **V2 静态场景库 + 轻量语义路由 + 精确覆盖**（采用）：无新增运行 API 消耗；关键词/场景路由使常见故事匹配到合适背景，另允许受控环境按来源键指定已上传的独立素材。
3. **发布时调用图像模型并自动上传微信**：可以每篇不同，但引入可用性、费用和网络权限风险，不适合先进行的数日观察试验。

## 设计

- V2 每栏目预备三种不同场景，最终资源图没有大面积文字或宣传面板；封面上部可以保留轻量栏目识别元素，但微信顶部已有公众号身份，优先以视觉主体区分栏目。
- 统一深蓝/青绿与暖光为潜界 AI 的视觉体系。海外创业志侧重人物真实工作场景，X 侧重商业信号，Product Hunt 侧重新产品，TrustMRR 周/月分别突出增长排行榜/趋势。
- 原始封面中心正方形必须有可读的单一主体；下方 18% 为空间较干净、对比足够的区域，便于微信自动叠加文章标题。
- V2 路由必须有 `off`（完全保持旧逻辑）和 `semantic` 模式；通过 `WECHAT_COVER_ROUTING=semantic` 显式开启。先匹配每个栏目内三个带标签的场景；无关键词时沿用原有 SHA-256 稳定哈希分配。
- `WECHAT_COVER_OVERRIDES_JSON` 可按准确 `source_key` 将单篇文章指定到已经上传的永久 `media_id`，适用于后续按文章独立生图；优先级高于静态池，仍遵循幂等和私密性。
- 裁剪必须校验 `0..1` 坐标、有效矩形、目标宽高比，不合法即停止创建草稿，不默默降级。媒体回退仍按已有栏目老封面配置执行。
- V2 本地素材打包给受控服务器上传，上传/切换生产环境必须经过 `dry-run`、测试和确认。发布器不允许不确定的微信 `draft/add` 结果重试。
- 提供不接触微信公众号的 `preview`/测试报告：语义选择、裁剪方版中心安全区、已有多栏目的回归测试。

## 不做的事

- 不修改已发表图文、不自动改写文章标题和正文、不公开群发、不上传或记录私有素材 ID。
- 不引入新的外部付费图片生成服务或扩张到 CMS 分发业务。

## 验收

1. 默认配置下既有测试与既有封面选择完全相同。
2. 开启语义路由后相同标题和来源键得到稳定选择；有精确覆盖时覆盖优先，其他文章不受影响。
3. 非法媒体 ID、裁剪坐标、未知场景配置在 `draft/add` 前失败。
4. V2 每张封面均适合微信的宽/方两种裁剪；缩小后的主体可识别，没有中央多行文字牌。
5. 生产部署有明确的可回滚开关与数日观察清单。
